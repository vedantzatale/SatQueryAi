# Datasets

None of these datasets are bundled with this repository — no copyrighted/proprietary
imagery is included. Each dataset adapter in `ml/datasets/` fails with a clear
`FileNotFoundError` (not a fabricated sample) when the expected files aren't present.
Final ISRO/SAC evaluation data must never be committed here or used in training/demo code.

| Dataset | Used for | Adapter | Expected layout |
|---|---|---|---|
| BigEarthNet-S1/S2 | Primary RS-VLM adaptation data | `ml/datasets/bigearthnet.py` | `root_dir/<patch_name>/<patch_name>_<BAND>.tif` + `<patch_name>_labels_metadata.json` per patch, exactly as distributed by BigEarthNet |
| VRSBench | VQA/captioning/grounding evaluation | `ml/datasets/vrsbench.py` | `root_dir/images/<image_id>.png` + `root_dir/<split>_annotations.json` (list of `{image_id, task, question, answer, bbox}`) |
| RSVQA (LR/HR) | VQA evaluation | `ml/datasets/rsvqa.py` | `root_dir/images/<img_id>.tif` + `root_dir/all_questions.json` + `root_dir/all_answers.json`, cross-referenced by id as in the standard RSVQA release |
| CDVQA | Change VQA evaluation | `ml/datasets/cdvqa.py` | `root_dir/images/<pair_id>_before.png` / `_after.png` + `root_dir/annotations.json` |

## Field-name caveat

VRSBench, RSVQA, and CDVQA have had multiple public releases with slightly different
file/field naming. The layouts above match the commonly-distributed structure at the time
this adapter was written; if a specific release differs, adjust the field names in the
relevant adapter's `__getitem__` rather than the calling code — that is exactly the
isolation `BaseDatasetAdapter` is for.

## Demo data is separate and synthetic

`data/demo/` is unrelated to the above — it's procedurally generated by
`scripts/generate_demo_data.py` for local development and the mock satellite provider.
It is never real satellite imagery and is always labeled `synthetic_demo` in
`data/demo/metadata/manifest.json`.

## Training/eval data directory convention

This build expects real datasets under `data/training/<dataset>` (fine-tuning) and
`data/eval/<dataset>` (evaluation) when you point `ml/training/configs/*.yaml` or the
`ml/evaluation/evaluate_*.py --root-dir` flag at them — these directories are gitignored
and never committed.
