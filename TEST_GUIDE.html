Take SatQuery AI for a test flight.

This is a self-guided tour of everything the app can do right now, in plain language. You don't need to read any code. Each "flight" below is a real thing to click through in your browser, what you should see when it works, and which of the five AI models is actually doing the work behind it.

00

Launch the app

Two programs need to be running at once: the backend (the brain — Python, port 8000) and the frontend (what you see — Next.js, port 3000). Open two separate terminal windows.

Backend terminal 1

  1. Open a terminal and go to the backend folder: 
    cd "C:\Users\Shivam\Downloads\temp web\SatQueryAi\backend"
  2. Start the server. Plain python isn't set up on this machine, so use the full path: 
    "C:\Users\Shivam\AppData\Local\Python\bin\python.exe" -m uvicorn app.main:app --reload --port 8000
  3. Wait for Uvicorn running on http://127.0.0.1:8000. Leave this window open — closing it stops the app.

Frontend terminal 2

  1. Open a second terminal and go to the frontend folder: 
    cd "C:\Users\Shivam\Downloads\temp web\SatQueryAi\frontend"
  2. Start it: 
    npm run dev
  3. Wait for Local: http://localhost:3000, then open that address in your browser and click through to /app.
The first question you ask will feel slow — that's expected. The query-understanding model (Qwen3-4B) runs on this machine's CPU, no GPU, so reading your question and deciding what to do about it takes roughly 60–100 seconds every time, not just the first time. Don't refresh — the spinner in the chat is genuinely thinking, not stuck. Everything else (change detection, image analysis) replies in a few seconds.
01

Meet the 5 models

Every answer SatQuery AI gives you is actually produced by one of these five components. Knowing which one is behind a given feature tells you what to expect from it.

Real

Qwen3-4B

The receptionist. Reads your question (English, Hindi, or Hinglish) and decides what kind of analysis you're asking for and which images/dates it needs.

Powers flights 1, 2, 6, 9 · ~60–100s per question on this CPU-only machine.

Real

ChangeFormer

The spot-the-difference expert. Given a "before" and "after" satellite image of the same place, it draws a pixel mask of exactly what changed.

Powers flight 4 · trained on the LEVIR-CD building-change dataset · a few seconds per pair.

Real

Prithvi-EO-2.0

The spectral analyst. Turns a 6-band multispectral image into a numeric fingerprint other tools can reason over, instead of treating it like an ordinary photo.

Powers flight 3 (multispectral half) · needs 6 real Sentinel-2 bands, not a 3-band photo.

Real

CROMA-base

The translator between optical and radar. Builds one shared representation from a normal (optical) image and a radar (SAR) image and checks whether they agree.

Powers flight 5 · needs 12 optical + 2 SAR bands · heaviest of the five.

Excluded — your choice

InternVL3-1B (remote-sensing finetuned)

Would be the one that describes a single image, answers open questions about it, and points at a region you ask about. You held this one back, so it still runs on a color-pattern heuristic, clearly labeled.

Would power flight 3 (VQA/captioning/grounding half) · drop its checkpoint in and ask to wire it in the same way as the other four.

02

Nine test flights

Work through these in order — later ones build on things you'll already have uploaded. Click "Mark flown" on each once you've seen the expected result; your progress is saved in this browser.

1 · Ask a plain question

feature 1feature 7feature 10

Goal: watch the real Qwen3 model turn your sentence into a structured plan and route it to the right tool.

  1. Go to /app, click New Analysis.
  2. Type: "What changed near Mumbai between 2020 and 2023?" and send it — with no image attached.
  3. Wait (~60–100s). It's reading and planning, not fetching anything yet.
What you should seeSince no image was attached and no date range was resolvable to real satellite catalogue coverage, the assistant should ask for more input or explain it needs imagery — it should not confidently invent a change percentage from nothing.

How to tell it's real: open the model registry page (link in the sidebar profile menu → Model Registry) and check qwen_agent — status should read healthy and is_mock: false.

2 · Speak Hindi or Hinglish

feature 17feature 1

Goal: confirm the interface itself switches language, and the model understands a non-English query.

  1. In the sidebar, click the language switcher (globe icon, under the search box) and choose हिन्दी or Hinglish.
  2. Watch the sidebar labels, empty-state suggestions, and composer hint text change immediately.
  3. Type a query in Hinglish, e.g. "Pichhle saal Pune mein built-up area badha hai kya?"
What you should seeThe UI chrome (buttons, categories, placeholders) is now in your chosen language and stays that way after a page refresh. Qwen3's plan (visible later in the Analysis Trace) should show "language": "hinglish".

This is the one flight with no mock fallback to compare against — the interface translation is new today, in three languages, for the sidebar/header/composer/empty-state.

3 · Look at one image

feature 2feature 3feature 12

Goal: see the one part of the app that's still on the heuristic mock — and understand why.

  1. Upload any optical satellite image (GeoTIFF, PNG, or JPEG) and ask "What is visible in this image?"
  2. Then ask "Where is the water?" — this exercises grounding (a highlighted box).
What you should seeA real, pixel-derived answer (percentage of water/vegetation/built-up color signature) — but every response carries demo_mode: true and a "basis" note saying it's a color-threshold heuristic, not a trained vision-language model. That's InternVL3-1B's job, and you excluded it.

This is the control group: compare its confidence badge and phrasing against flight 4 or 5, which run genuinely trained models.

4 · Compare two dates

feature 4feature 5feature 13

Goal: run ChangeFormer for real and get a genuine change mask with an area estimate.

  1. Start a new analysis, attach two optical images of the same area from different dates (before/after).
  2. Ask: "What changed between these two images, and by how much?"
  3. Wait a few seconds — this one is fast, no CPU LLM bottleneck.
What you should seeA highlighted change mask overlaid on the image, a changed-area percentage, and "basis": "ChangeFormer (LEVIR-CD pretrained checkpoint) segmentation head" with demo_mode: false in the trace.

If the two images have different pixel dimensions after alignment, you should get a clear rejection message, not a guessed answer — try it once to see the honest failure path too.

5 · Fuse optical + radar

feature 6

Goal: see CROMA combine two very different sensor types into one judgment.

  1. Attach one optical/multispectral image and one SAR (radar) image of the same area.
  2. Ask: "Compare optical and SAR imagery for this area."
What you should seeAn "agree" / "disagree" verdict between the two sensors, backed by "basis": "CROMA-base joint encoder cosine similarity...". If your images have fewer than 12 optical or 2 SAR bands, expect a clear validation error explaining exactly why — CROMA was pretrained on that exact band count and can't be guessed around.

This is the heaviest of the five models — if your machine is short on free RAM, this is the flight most likely to feel sluggish.

Goal: ask for imagery without uploading anything and let the app find it.

  1. Start a new analysis with no attachments.

7 · Trust the answer

feature 8feature 14feature 15feature 16

Goal: check the app explains itself instead of just handing you an answer.

  1. On any completed analysis (e.g. from flight 4), find the confidence badge next to the answer.
  2. Click "How was this analyzed?" to open the transparency panel.
  3. Try uploading an unsupported file (e.g. a .txt file) to see input validation reject it up front.

What you should seeA real downloadable PDF and GeoJSON file; the follow-up question resolved using earlier context (Qwen3 now receives your last few messages, not just the new one); the rename/delete actually persist after a page refresh — they're wired to the backend now, not just local UI state.

Goal: see all five models (plus one unreleased placeholder) listed with live health, in one place.

04

If something looks wrong

A question is taking forever and I don't know if it's stuck
Normal, if it's the first step of understanding your question — Qwen3-4B runs on CPU here and genuinely needs 60–100 seconds per query. Look at the terminal running uvicorn; as long as you don't see a Python error/traceback, it's working. Give it up to 3 minutes before assuming it's hung.
I got a "too few bands" error on the SAR/multispectral flight
That's correct behavior, not a bug. Prithvi-EO-2.0 needs exactly 6 real Sentinel-2 bands and CROMA needs 12 optical + 2 SAR bands — they were trained on those exact band counts and can't meaningfully process a plain 3-band RGB photo. Use real multispectral/SAR source imagery for those two flights specifically; ordinary images are fine for flights 3 and 4.
The backend won't start / "port already in use"
Something is already listening on 8000 — likely a previous uvicorn you forgot to close. Close that terminal window, or start this one with --port 8001 and change NEXT_PUBLIC_API_BASE_URL in the frontend's environment to match.
Everything feels slow / my computer fans spin up
This machine has 16GB RAM and no GPU. Qwen3-4B alone holds ~8GB while loaded. Close other heavy apps before flight 1, and avoid running flight 5 (CROMA, the heaviest model) at the same time as a fresh Qwen3 query.
I want to see the "before" mock behavior again, to compare
Open .env at the project root, blank out (delete the value after the =) any of AGENT_MODEL_PATH, PRITHVI_MODEL_PATH, CHANGE_MODEL_PATH, CROMA_MODEL_PATH, save, and restart the backend terminal. That one model instantly falls back to its heuristic mock — nothing else changes.
Can I delete models.zip at the project root?
Yes — it's the original 10GB upload and everything inside it has already been extracted into models/weights/, which is what the app actually reads from. Deleting the zip frees ~10GB and changes nothing about how the app runs.
